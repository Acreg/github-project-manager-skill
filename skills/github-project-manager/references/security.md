# 源码筛选、秘密检查与公开分发

## 最低要求

- 本地首次导入前，检查父级与项目 AGENTS、最新 README/计划；明确“用户指定的多个并列方案”和“复制式历史版本目录”的不同。
- 必须有：运行源码、构建配置、依赖锁、数据库**迁移源码**、单元测试、必要 testdata、Go //go:embed 所引用的已生成运行时静态资源、部署模板及关键 Markdown。
- 默认不上传：.env、密码、Token、ssh key、数据库 .db/.sqlite/-wal/-shm、日志、运行输出、backup、node_modules、dist（但 Go embed 等被代码实际引用的 dist 是例外）、编译二进制、旧版本 ZIP/TAR。
- 检测硬编码配置秘钥、私钥 PEM、GitHub token、带 key/token 的 URL。不要显示匹配凭据正文，只报告相对路径、行号、类别。误命中单元测试样例需区分。
- 不将 .gitignore 当秘密保护：被暂存的文件仍需要检查；Git 历史已上传的真实密钥需轮换，删当前文件无法清除旧历史。

## 公共仓库更严格

- 用户明确选择 Public 才创建 Public，不能把原本 Private 的用户项目改公开。
- 公开 Skill/工具仓库只发布**通用规则和代码**，不能包含用户路径、个人资料、私人业务计划、连接配置、真实 Token、受限图片或字体。
- 示例使用 OWNER/REPO、vX.Y.Z、project_dir 等占位符，不引用真实私人仓库 URL、服务器地址或特定项目机密。
- 除非用户明确要求变更权限，不改协作者、分支保护、组织权限，也不授予所有 GitHub 仓库权限给第三方。

## 缩小写入范围

上传与脱敏**只作用于隔离临时副本**。向仓库提交前人工核对 git diff --cached / tree file list；原项目不初始化、不删除、不更新生产。首次发布后读回 private、提交 SHA、递归文件树数量和关键文件。失败时保留临时副本以供核实。

本 Skill 的 run.py 做的是**初步筛选和高可信格式检查**，不能自动证明“绝对无密钥”或“复制结果一定能编译”。需要人工补全被忽略的资源，复杂项目应运行实际构建测试。
